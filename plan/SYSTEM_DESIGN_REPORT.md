# Отчет о внедрении System Design и архитектурной устойчивости: BA (Business Analyzer)

> **Статус:** Имплементировано  
> **Область:** Spatial Caching (Geohash Grid), Dataset In-Memory Cache with Mtime Invalidation, Token Bucket Rate Limiting, HTTP Resilience (Timeouts & Backoff)  
> **Дата аудита и внедрения:** Октябрь 2026

---

## 1. Контекст и архитектурные вызовы

`BA` (Business Analyzer) выполняет геопространственный скоринг коммерческой привлекательности локаций для ритейла и общепита на основе наборов OpenStreetMap POI.
До внедрения проекта:
1. **Тяжелый повторный парсинг CSV:** При каждом запросе к `/api/score`, `/api/v1/score/location` и `/api/report` сервер читал файл `businesses.csv` (1.6+ МБ) с диска и парсил строки с нуля.
2. **O(N) расчет расстояний на каждый запрос:** Вычисление плотности и скоринга конкурирующих и комплементарных точек повторно выполнялось даже для соседних или идентичных координат.
3. **Отсутствие защиты от абьюза и скрейпинга:** Эндпоинты гео-скоринга и генерации отчетов не имели ограничения частоты запросов, что создавало риск исчерпания CPU.

## 2. Реализованные архитектурные решения

### 2.1. Spatial Geohash Caching (`src/services/spatial-cache.ts`)
* **Geohash Encoding:** Стандартный алгоритм кодирования координат в Base32 Geohash с настраиваемой точностью:
  - Precision 6: ~1.2 км x 0.61 км (районный уровень)
  - Precision 7: ~153 м x 153 м (уличный / квартальный уровень, дефолт для скоринга)
  - Precision 8: ~38 м x 19 м (микро-локация / здание)
* **`SpatialScoreCache`:** LRU-кэш с ограничением размера (по умолчанию 5000 записей) и TTL (15 минут). Запросы в пределах одной Geohash-ячейки возвращают готовый результат с заголовком `X-Cache: HIT`.
* **`POIDatasetCache`:** Кэш распарсенного набора POI и строк таблицы `businesses.csv` в оперативной памяти с автоматической проверкой `mtimeMs`. При обновлении датасета через `/generate` кэш немедленно инвалидируется.

### 2.2. Token Bucket Rate Limiting (`src/middleware/rate-limiter.ts`)
* Алгоритм Token Bucket для защиты API и виджетов:
  - `/api/score`: 120 req / мин
  - `/api/v1/score/*`: 120 req / мин
  - `/api/report`: 60 req / мин
  - `/generate`: 10 req / мин
* Стандартные заголовки: `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`, а при превышении — HTTP 429 и `Retry-After`.

### 2.3. Сетевая устойчивость внешних сервисов (`src/utils/resilient-fetch.ts`)
* Отказоустойчивый `resilientFetch` в соответствии с разделом 3.1 мастер-архитектуры:
  - Контроль таймаута через `AbortController` (по умолчанию 5000 мс)
  - Экспоненциальный бэкофф с полным джиттером (Full Jitter) для 5xx и 429 статусов
  - Защита от бесконечных повторов (`maxRetries = 3`).
